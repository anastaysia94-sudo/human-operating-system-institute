# HOSI WordPress.com Free — Progress, Assessment & Certificate Workflows

## Purpose

Define what the $0 public campus can honestly support and what must wait for an authenticated LMS/backend.

## 1. Progress tracking on Free

### Supported now
HOSI can publish a manual progress checklist containing:
- lesson ID
- lesson title
- module
- optional completion box
- optional reflection/homework box
- capstone prerequisites

Learners can:
- print it
- save a copy locally
- copy it into their own notes
- maintain their own Scholar Portfolio

### Not claimed on Free
HOSI must not claim server-side personalized progress unless such a system actually exists.

Do not use:
- public comments as completion records
- a public form as a health/diagnosis profile
- browser cookies as if they were durable academic records
- unverified checkbox screenshots as identity-verified course completion

## 2. Course checklist structure

Recommended columns:

| Lesson | Title | Read | Self-check | Homework/reflection | Notes |
|---|---|---|---|---|---|
| HOSI-101-001 | Welcome to HOSI | ☐ | ☐ | ☐ | |

Create one checklist per 10-lesson module plus a 200-lesson master checklist.

## 3. Knowledge checks

Knowledge checks are formative.

Use:
- multiple-choice questions
- short-answer prompts
- concept comparisons
- evidence-rating questions
- scope/ethics questions

Native WordPress **Details blocks** may reveal answer explanations after the learner attempts the question.

Label:
**Knowledge check / self-check**

Do not label:
- diagnostic test
- cognitive evaluation
- validated screening instrument
- graded exam

unless those claims are independently true and governed appropriately.

## 4. Homework

Homework can ask learners to:
- explain concepts
- compare evidence
- create a systems map
- apply a learning strategy
- critique a claim
- build a research table
- analyze a fictional case

Homework should not require disclosure of trauma, diagnosis, treatment, medication, faith, family conflict, or other sensitive personal information.

Always provide a fictional/example alternative where a personal reflection could become sensitive.

## 5. Formal assessments

The public Free site can publish assessment questions and rubrics, but it cannot honestly claim secure graded assessment without an actual grading/identity workflow.

Before formal scored assessment is used for credentials, define:
- learner identity rules
- attempt rules
- accommodation process
- grading process
- appeal/correction process
- score retention
- privacy/access control
- academic-integrity rules

## 6. Learner dashboard on Free

A Free-plan `Learner Dashboard` should be labeled **Start Here / Learner Toolkit** unless persistent personal state actually exists.

It can contain:
- course links
- module checklist downloads/copyable tables
- study-path links
- evidence guide
- Scholar Portfolio instructions
- capstone rubric
- accessibility resources

It must not visually imply that WordPress knows what the visitor personally completed when it does not.

## 7. Scholar Portfolio

Until a private learner system exists, HOSI may define a learner-controlled Scholar Portfolio containing:
- completed-course checklist
- selected homework
- capstone work
- research-synthesis work
- optional personal reflections chosen by the learner
- certificate records later issued by HOSI

The learner decides which personal reflections belong in a submitted portfolio. Private Atlas content is not automatically part of the portfolio.

## 8. Certificate terminology

Allowed only when issuance requirements are actually met:
- Certificate of Completion
- Certificate in HOSI Studies
- Course Completion
- Scholar Portfolio

Do not claim:
- accredited degree
- professional license
- medical license
- board certification
- accredited university status

unless legitimately obtained.

## 9. Manual certificate workflow before LMS automation

A future manual workflow may be acceptable after credential governance passes:

1. Learner submits the required non-sensitive completion evidence.
2. Authorized reviewer checks completion/assessment requirements.
3. Reviewer records decision.
4. Certificate receives a unique credential ID.
5. Issuance date, course/version, reviewer, and revocation state are recorded.
6. Learner receives the certificate.
7. HOSI retains only the minimum credential record required by policy.

Do not require government ID merely because a certificate exists unless the credential policy has a justified identity requirement.

## 10. Automated certificate upgrade gate

Automate only when HOSI has:
- authenticated accounts
- reliable progress records
- assessment records
- credential policy
- privacy and retention rules
- issuance/revocation records
- accessible certificate format
- fraud/abuse controls

Then compare a compatible LMS/backend against actual requirements.

## 11. Capstone

HOSI-101 capstone should assess:
- systems reasoning
- evidence calibration
- distinction between correlation/causation
- uncertainty
- ethical scope
- application
- research synthesis

It should not assess whether a learner agrees with the founder, discloses personal history, or prefers one legitimate treatment option.

## 12. Accessibility and accommodations

Formal assessment design must plan for:
- extra time where appropriate
- screen readers
- keyboard navigation
- low-vision access
- cognitive-load reduction
- alternative response formats where legitimate
- no penalty for declining personal disclosure

## 13. Upgrade trigger table

| Requirement | Free-site solution | Upgrade/backend trigger |
|---|---|---|
| Lesson publishing | Pages/posts | None |
| Search | Native Search block | Only if advanced search is required |
| Course indexes | Categories + Query Loop + manual ordered lists | Only if complex enrollment/state is required |
| Self-checks | Questions + Details blocks | Automated grading |
| Progress | Learner-controlled checklist | Persistent authenticated progress |
| Dashboard | Static learner toolkit | Personalized dashboard |
| Certificates | Policy/manual future process | Automated verified issuance |
| Atlas | Public explainer only | Privacy-safe authenticated Atlas backend |
| LMS | No plugin dependency | Upgrade when exact LMS requirement exists |

The upgrade decision should solve a real blocked requirement, not the emotional discomfort of seeing a feature labeled “manual.”
