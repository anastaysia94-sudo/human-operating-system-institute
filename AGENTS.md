## Operating rules
1. Continue existing work; do not restart it.
2. Inspect existing files before editing.
3. Prefer small, reviewable commits/PRs.
4. Keep source-of-truth content in portable text formats where practical.
5. Never fabricate citations, research findings, credentials, accreditation, tests, reviewers, or completed deployments.
6. For medical/psychological content, distinguish evidence, hypothesis, expert guidance, lived experience, and founder philosophy.
7. Never convert a personal adverse treatment experience into a universal clinical claim.
8. Do not tell learners to start, stop, or change prescribed treatment based on HOSI educational material.
9. Atlas features must preserve consent, user ownership, export/delete, provenance, and non-diagnostic boundaries.
10. Generated code is not complete until it builds/tests successfully where applicable.
11. Generated academic content is not final until the required evidence and review gates pass.
12. Update status documentation when a meaningful workstream changes.

## 100% rule
Never mark the project 100% merely because files have been generated. 100% requires the project's academic, evidence, technical, privacy, security, accessibility, governance, QA, pilot, and external-authorization gates to be genuinely satisfied.

## Default deliverable format
When completing a task, report:
- files changed
- tests run
- evidence/source checks
- known limitations
- remaining blockers
- commit/PR reference
